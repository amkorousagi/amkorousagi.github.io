Unity에서 카메라나 이미지 텍스처를 받아 비전 모델에 넣을 때, **에디터와 데스크톱 빌드에서는 잘 되는데 Android·iOS 빌드에서만 결과가 이상한** 일을 겪었습니다. 모델이나 가중치 문제가 아니라 텍스처를 텐서로 바꾸는 과정에서 생긴 문제였고, 원인은 세 가지로 정리됐습니다.

## 1. y축 원점이 다르다

Unity 텍스처 좌표는 **왼쪽 아래**가 원점이고, 대부분의 비전 모델은 이미지가 **왼쪽 위** 원점(첫 행이 이미지 맨 위)이라고 가정하고 학습됩니다. 그대로 넣으면 위아래가 뒤집힌 이미지를 넣는 셈입니다. 얼굴 검출처럼 강건한 모델은 그래도 어느 정도 동작해서 문제를 늦게 알아차리게 됩니다.

Compute Shader에서 텐서 버퍼를 채울 때 행 인덱스를 `height - 1 - y`로 뒤집어 씁니다.

## 2. 레이아웃마다 인덱스 계산이 다르다

같은 RGB 픽셀이라도 텐서 레이아웃에 따라 버퍼 위치가 다릅니다.

**NHWC** — 픽셀마다 채널이 붙어 있습니다(TensorFlow 계열 모델).

```hlsl
int row   = height - 1 - id.y;            // y 원점 뒤집기
int index = (row * width + id.x) * 3;
_Output[index + 0] = pixel.r;
_Output[index + 1] = pixel.g;
_Output[index + 2] = pixel.b;
```

**NCHW** — 채널마다 평면 하나씩입니다(PyTorch 계열 모델).

```hlsl
int row   = height - 1 - id.y;
int p     = row * width + id.x;
int plane = width * height;
_Output[plane * 0 + p] = pixel.r;
_Output[plane * 1 + p] = pixel.g;
_Output[plane * 2 + p] = pixel.b;
```

파이프라인에 두 계열 모델이 섞여 있으면 레이아웃을 하나로 통일하는 편이 낫습니다. 그래프 앞의 `Transpose`를 없애는 방법은 [ONNX 그래프 손보기](/blog/onnx-graph-tuning-for-mobile/)에 정리했습니다.

## 3. 기기에서만 알파 채널이 붙는다

마지막이 가장 찾기 어려웠습니다. 증상은 이랬습니다.

| 텍스처 | 에디터 | 휴대폰 |
|---|---|---|
| 파일로 저장했다 불러온 텍스처 | 정상 | 정상 |
| 런타임에 잘라 만든 텍스처 | 정상 | **비정상** |

텍스처 → 텐서 변환 결과의 shape를 찍어 보니 차이가 바로 보였습니다.

- 저장된 텍스처는 RGB라 `(1, 3, H, W)`
- 런타임에 만든 텍스처는 RGBA라 `(1, 4, H, W)`

에디터와 데스크톱에서는 4채널 입력이어도 결과가 정상이었지만, 기기 빌드에서는 그렇지 않았습니다. 빌드 설정의 텍스처 압축 형식(Android 기본값은 RGB 텍스처에 ETC, RGBA 텍스처에 ETC2)을 바꾸면 증상이 달라지는 것도 같은 원인 때문이었습니다. 라이트맵 인코딩, 품질 레벨, 그래픽 티어 같은 설정은 무관했습니다.

해결은 단순합니다. **텍스처 형식에 기대지 말고, 변환 단계에서 채널 수를 명시적으로 3으로 고정합니다.** 위 셰이더처럼 r·g·b만 골라 쓰고 텐서 shape를 `(1, 3, H, W)`로 만든 뒤, 추론 전에 shape를 assert합니다.

## 디버깅 순서

1. **텐서 shape부터 찍는다.** 채널 수가 맞는지 확인하면 절반은 끝납니다
2. **입력 텐서를 이미지로 되돌려 저장해 본다.** 위아래가 뒤집혔는지, 색 순서(RGB/BGR)가 맞는지 눈으로 바로 보입니다
3. **같은 입력을 에디터와 기기에서 넣고 텐서 값을 비교한다.** 저장된 텍스처와 런타임 텍스처를 나눠서 비교하면 원인이 데이터인지 경로인지 가를 수 있습니다

## 정리

- Unity 텍스처는 왼쪽 아래 원점이다. 행을 뒤집어 쓴다
- NHWC와 NCHW는 인덱스 계산이 다르다. 파이프라인 안에서는 하나로 통일한다
- 런타임 텍스처는 기기에서 RGBA가 될 수 있다. 채널 수를 변환 단계에서 고정하고 shape를 검사한다
