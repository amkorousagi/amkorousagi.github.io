게임 엔진이나 카메라 미리보기처럼 **화면을 계속 그리는 앱 안에서** 작은 비전 모델(검출·랜드마크 같은 수 MB급 모델)을 돌리면, "GPU 백엔드로 바꿨더니 오히려 느려졌다"거나 "처음엔 괜찮다가 점점 밀린다"는 일이 생깁니다. 이 글은 그런 상황에서 원인을 가려내는 방법과 흔히 쓰는 해결책을 정리한 것입니다.

## 왜 생기나

**1. 결과를 CPU로 가져오는 비용**
GPU에서 계산한 결과를 CPU 코드(후처리, 게임 로직)가 쓰려면 GPU 작업이 끝날 때까지 기다렸다가 메모리를 복사해야 합니다(readback). 모델이 작을수록 계산 시간은 짧아지지만 이 기다림과 복사 비용은 줄지 않아, 전체 시간에서 차지하는 비율이 커집니다.

**2. 출력 텐서 개수만큼 반복되는 동기화**
검출·랜드마크 모델은 출력이 여러 개인 경우가 많습니다(좌표, 점수, 보조 출력 등). 출력마다 따로 읽으면 한 번 추론에 동기화가 여러 번 일어납니다.

**3. 렌더링과의 GPU 경쟁**
앱이 같은 GPU로 화면을 그리고 있으면 추론 작업과 렌더링 작업이 서로를 기다립니다. readback을 메인(렌더) 스레드에서 동기로 하면 그동안 화면도 멈춥니다.

**4. 밀림이 쌓이는 루프 구조**
"추론 → 일정 시간 대기 → 다시 추론" 식의 루프는 한 번 늦어지면 다음 차례도 늦어집니다. 처음엔 괜찮다가 시간이 지날수록 지연이 커진다면 연산량보다 이쪽을 먼저 의심할 만합니다. 연산량이 원인이라면 처음부터 끝까지 비슷하게 느려야 합니다.

## 가려내는 방법

- **단계별로 시간을 찍는다.** 입력 준비 / 추론 실행(dispatch) / 결과 가져오기(readback) / 후처리를 따로 잽니다. readback 구간이 크면 모델을 줄여도 효과가 작습니다
- **백엔드를 같은 절차로 비교한다.** CPU와 GPU 백엔드를 같은 입력·같은 기기·같은 부하(렌더링이 도는 상태)에서 잽니다. 빈 화면에서 잰 숫자는 실제 앱에서 다르게 나옵니다
- **평균만 보지 않는다.** 중앙값, p95, 그리고 화면 프레임 드랍을 같이 봅니다. 사용자가 느끼는 것은 평균이 아니라 끊김입니다
- **판정 기준을 측정 전에 정한다.** 예를 들어 "지연이 20% 이상 줄고 프레임이 유지되면 채택"처럼 미리 정해 두면, 결과를 보고 기준을 바꾸는 일을 막을 수 있습니다

## 줄이는 방법

### 1. 출력을 하나로 합친다
모델 그래프 끝에 출력들을 평탄화(flatten)해 이어 붙이는(concat) 노드를 넣어 출력 텐서를 하나로 만듭니다. 받는 쪽은 각 출력의 모양을 알고 있으니 위치(오프셋)로 다시 나눠 읽으면 됩니다. 동기화가 추론당 한 번으로 줄어듭니다.

### 2. 작은 모델은 CPU 백엔드도 후보에 넣는다
"GPU가 빠르다"는 가정을 측정으로 확인합니다. 모델이 작고 GPU가 렌더링에 바쁜 앱에서는 CPU 백엔드(SIMD 최적화 커널)가 readback이 없어 더 빠르고 안정적인 경우가 많습니다.

### 3. 결과는 비동기로 받는다
동기 readback이 평균은 조금 빠르더라도 가끔 프레임을 떨어뜨린다면, 평균이 약간 늦더라도 프레임 드랍이 없는 비동기 방식을 고르는 편이 사용자 경험에 낫습니다. 이런 트레이드오프는 선택 이유와 함께 기록해 둡니다.

### 4. 루프를 프레임에 맞추거나 전용 스레드로 뺀다
시간 대기 기반 루프 대신 프레임 단위로 도는 루프를 쓰면 지연이 쌓이지 않습니다. 더 나아가 추론을 렌더링과 분리된 전용 스레드(네이티브 런타임)로 옮기면 서로 기다리는 일 자체를 없앨 수 있습니다.

## 체크리스트

- [ ] 추론 1회를 입력 준비 / 실행 / readback / 후처리로 나눠 쟀는가
- [ ] 렌더링이 도는 실제 부하에서 CPU·GPU 백엔드를 같은 절차로 비교했는가
- [ ] 중앙값·p95·프레임 드랍을 함께 봤는가
- [ ] 출력 텐서가 여러 개라면 하나로 합칠 수 있는가
- [ ] readback을 렌더 스레드에서 동기로 하고 있지 않은가
- [ ] 지연이 시간이 지날수록 커지는가 (루프 구조 의심)

모델을 줄이거나 양자화하기 전에 이 항목부터 확인하면, 출력을 바꾸지 않고도 지연을 크게 줄일 수 있는 경우가 많습니다. 양자화처럼 출력이 바뀌는 최적화를 언제 쓸 수 있는지는 다음 글에서 공개 모델로 직접 측정해 정리하겠습니다.
