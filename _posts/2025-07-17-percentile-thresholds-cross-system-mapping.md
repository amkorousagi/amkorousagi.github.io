사용자가 처음 기능을 쓸 때 개인 보정(캘리브레이션)을 마치기 전이나 보정에 실패했을 때는 **기본값**을 씁니다. 예를 들어 "위·아래·좌·우를 봤을 때의 최대 각도"의 기본값이 있고, 판정 기준은 그 값의 70%입니다. 이 기본값이 너무 크면 아무리 봐도 인정되지 않고, 너무 작으면 살짝만 움직여도 인정됩니다. 측정 엔진을 바꾸면서 이 기본값을 다시 정해야 했습니다.

## 1. 목표를 "통과율"로 정의한다

"좋은 기본값"을 이렇게 정의했습니다.

> 기본값 × 0.7을 기준으로 할 때, 과거 실제 사용자 보정값 중 **몇 %가 그 기준을 넘는가**(=기본값을 써도 인정받는 사용자 비율)

그러면 기본값은 목표 통과율(예: 95%, 90%)에 해당하는 **백분위**로 바로 구해집니다. 방향마다 분포가 다르므로 방향별로 따로 구합니다.

```python
def default_for_pass_rate(values, target=0.95, ratio=0.7):
    v = np.sort(np.abs(values))
    prev = None
    for q in np.linspace(0, 1, 101):
        cand = np.quantile(v, q)
        if np.mean(v >= cand * ratio) < target:
            return prev
        prev = cand
    return prev
```

## 2. 데이터 정리가 절반이다

- 과거 기록에는 **이미 기본값이 그대로 저장된 행**(보정을 안 한 경우)과 **중복**이 많았습니다. 이걸 빼지 않으면 기본값이 자기 자신을 근거로 다시 정해집니다. 한 시스템은 수백 행 중 수십 행만 남았습니다
- 방향마다 분포 모양이 달랐습니다. 아래 방향은 최솟값은 비슷한데 평균과 퍼짐이 달라, 이상치 기준을 둘지 따로 검토했습니다

## 3. 두 측정 시스템 사이 환산 — 구간별로

새 엔진의 데이터가 아직 적어서, 오래 쓰던 기준 시스템의 많은 데이터를 활용하고 싶었습니다. 두 시스템으로 **같은 순간을 동시에 측정한 데이터**를 모아 관계를 봤습니다.

- 전체를 직선 하나로 맞추면 맞지 않았습니다. **부호(방향)에 따라 기울기가 달랐습니다.** 예를 들어 세로축은 위쪽과 아래쪽 기울기가 크게 달랐고, 가로축은 좌우가 비슷했습니다
- 그래서 방향별로 원점을 지나는 기울기를 따로 맞췄습니다(구간별 선형 환산)
- 0 근처 값은 잡음이 커서 기울기를 왜곡하므로, 작은 값 구간을 빼고 맞췄습니다

이렇게 하면 기준 시스템 데이터로 구한 백분위 기본값을 새 시스템 단위로 옮길 수 있습니다.

## 4. 후보를 여러 개 만들고 비교한다

| 후보 | 근거 |
|---|---|
| A | 새 시스템 데이터의 95% 통과 백분위 |
| B | 새 시스템 데이터의 90% 통과 백분위 |
| C | 기존 기본값을 환산식으로 옮긴 값 |
| D, E | 기준 시스템 데이터의 95%/90% 통과 백분위를 환산 |

후보끼리 크게 어긋나는 방향(예: 아래쪽)은 **어느 한쪽의 근거가 약하다는 신호**입니다. 이번에는 아래쪽에서 후보 간 차이가 커서, 그 방향은 데이터를 더 모은 뒤 다시 정하기로 했습니다.

## 정리

- 기본값을 "목표 통과율"로 정의하면 백분위 하나로 계산된다
- 기본값이 그대로 저장된 행과 중복을 먼저 뺀다
- 두 측정 시스템은 동시 측정 데이터로, 방향(구간)별로 환산한다
- 후보 여러 개를 나란히 놓고, 서로 어긋나는 곳을 근거가 약한 곳으로 본다
