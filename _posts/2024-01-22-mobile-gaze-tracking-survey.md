게임 엔진으로 만든 모바일 앱에 시선 추적을 넣어야 했습니다. 조건은 두 가지였습니다. **별도 장비 없이 기기의 전면 카메라만** 쓸 것, 그리고 **Android와 iOS 모두**에서 돌 것. 시작하기 전에 어떤 선택지가 있는지 조사한 결과를 정리합니다.

## 1. 기성 플랫폼·SDK

| 분류 | 예 | 모바일 전면 카메라로 쓸 수 있나 |
|---|---|---|
| AR 프레임워크 | ARKit(iOS), ARCore(Android) | ARKit은 얼굴·눈 방향을 주지만 **iOS·TrueDepth 기기 한정**. ARCore에는 시선 추적이 없음 |
| XR 기기 SDK | HoloLens, Vive, Quest, OpenXR 등 | 헤드셋 내장 아이트래커용이라 해당 없음 |
| 전용 장비 SDK | Tobii 등 | 외부 아이트래커 하드웨어 필요 |
| 상용 모바일 SDK | 일부 회사의 카메라 기반 SDK | 유료·체험 기간, 플랫폼·엔진 지원 범위 확인 필요 |

결론적으로 **두 플랫폼에서 같은 출력을 주는 무료 모바일 시선 추적 SDK는 찾기 어려웠습니다.** iOS만 보면 ARKit이 가장 쉬운 답이지만, Android에서 같은 값을 얻을 방법이 없습니다.

## 2. 직접 만드는 경로

공개 모델을 조합해 파이프라인을 만드는 쪽이 현실적이었습니다.

```text
얼굴 검출 → 얼굴 랜드마크(+홍채) → 머리 자세 → 시선 방향 계산
```

- Google MediaPipe의 얼굴 검출·얼굴 메시·홍채 모델은 공개되어 있고, 웹캠 하나로 "랜드마크 → 시선"을 계산하는 예제도 많습니다
- 시선 추정 자체를 학습한 딥러닝 모델(appearance-based gaze estimation)도 있지만, 데이터·기기 차이에 민감해 처음에는 **랜드마크 기하 기반**으로 시작하는 편이 디버깅이 쉽습니다
- 정답이 필요할 때는 **ARKit을 기준 데이터**로 놓고 같은 순간의 값을 동시에 기록해 비교·환산하는 방법을 생각할 수 있습니다

## 3. 공개 모델을 원하는 런타임으로 옮기기

MediaPipe 모델은 `.tflite` 형식입니다. 게임 엔진의 추론 엔진이나 ONNX Runtime에서 쓰려면 변환이 필요합니다.

1. 모델 파일 찾기: 예전에는 GitHub 저장소에 있었지만 지금은 별도 저장소로 옮겨졌습니다. 설치된 `mediapipe` 파이썬 패키지 폴더 안(`mediapipe/modules/face_landmark/` 등)에서 바로 찾을 수 있습니다
2. 변환:

```bash
python -m tf2onnx.convert --opset 13 --tflite face_landmark.tflite --output face_landmark.onnx
```

3. 변환 후 같은 입력으로 원본과 출력을 비교합니다. 이때 입력 레이아웃(NHWC↔NCHW)과 정규화 범위(0~1, −1~1)가 가장 흔한 실수 지점입니다

변환된 그래프에는 원래 런타임에 맞춘 흔적(Transpose, Expand 등)이 남아 있는 경우가 많아, 나중에 성능 최적화의 출발점이 됩니다([ONNX 그래프 손보기](/blog/onnx-graph-tuning-for-mobile/)).

## 4. 처음부터 염두에 둘 것

- **거리를 모르면 각도 오차가 생긴다.** 랜드마크 기하로 시선을 계산하면 얼굴까지의 거리 추정이 정확도에 바로 영향을 줍니다([거리 추정](/blog/pinhole-distance-iris/))
- **플랫폼 간 값 일치.** 한쪽만 기성 SDK를 쓰면 두 플랫폼의 값 정의가 달라져, 판정 기준을 따로 관리해야 합니다
- **저사양 기기.** 데모는 최신 기기에서 잘 돌아도 실제 사용자 기기에서는 수 배 느릴 수 있습니다. 목표 기기를 먼저 정합니다

## 정리

- 모바일 전면 카메라 + 크로스플랫폼 조건이면 기성 SDK보다 공개 모델 조합이 현실적이다
- MediaPipe 모델은 패키지 안에서 찾아 tf2onnx로 옮기고, 레이아웃·정규화부터 맞춘다
- 거리·플랫폼 일치·저사양 기기를 초기 설계 조건으로 넣는다
