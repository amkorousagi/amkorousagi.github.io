카메라 기반 기능은 렌즈에 지문 기름이 묻거나 물방울·얼룩이 생기면 조용히 정확도가 떨어집니다. 사용자는 이유를 모른 채 "인식이 잘 안 된다"고만 느낍니다. 그래서 **카메라 영상 자체의 이상**을 감지해 사용자에게 렌즈를 닦으라고 알려 주는 기능을 만들었습니다.

## 1. 무엇을 "비정상"으로 볼지부터 좁힌다

후보를 쭉 적은 뒤, 기존 기능으로 이미 잡히는 것(얼굴 없음, 너무 어두움, 거리·각도 이탈, 여러 명)과 이번 범위가 아닌 것(마스크, 모자, 손으로 가림 등)을 지웠습니다. 남은 것은 **카메라 자체의 이상** 세 가지였습니다.

- **흐림(Blur)**: 지문, 물방울, 얼룩
- **역광·노출 불균형**
- **가림(Occlusion)**: 거치대·케이스 부품

## 2. 모델부터 쓰지 않았다

물체 검출·깊이 추정·분할 공개 모델을 데모로 시험해 봤지만, 거치대 같은 장애물이나 뿌연 렌즈는 잘 잡지 못했고 모델도 수백 MB로 너무 컸습니다. 흐림에는 고전적인 지표가 더 잘 맞았습니다.

## 3. 라플라시안 분산

이미지에 라플라시안 커널(2차 미분)을 적용하면 경계에서 큰 값이 나옵니다. 선명한 영상은 경계가 많아 **응답의 분산이 크고**, 흐린 영상은 작습니다.

```text
K = [[0, 1, 0],
     [1,-4, 1],
     [0, 1, 0]]
흐림 점수 = Var(K * gray)
```

- **영역별로 계산**합니다. 위·아래·왼쪽·오른쪽 반쪽마다 분산을 따로 구하면, 렌즈 한쪽만 얼룩진 경우나 한쪽이 가려진 경우를 구분할 수 있습니다
- **임계값은 해상도에 맞춰 조정**합니다. 분산 값은 이미지 크기에 따라 달라지므로, 기준 해상도에서 정한 임계값을 현재 영역 크기 비율로 환산합니다
- 파이썬 데모로 먼저 깨끗한 렌즈 / 지문 / 물방울 / 가림 사진의 점수 분포를 보고 임계값 범위를 정했습니다

## 4. CPU 200ms+ → Compute Shader 20ms+

처음 구현은 텍스처 픽셀을 CPU로 읽어 반복문으로 계산했고, 고해상도에서 **200ms가 넘었습니다.** 매 프레임은커녕 주기적으로 돌리기도 부담스러웠습니다. 라플라시안 계산을 GPU 컴퓨트 셰이더로 옮겼습니다.

```hlsl
#pragma kernel CSMain
Texture2D<float4> _InputTex;
RWStructuredBuffer<float> _Lap;
int _Width, _Height;
SamplerState samplerPointClamp;

[numthreads(8,8,1)]
void CSMain(uint3 id : SV_DispatchThreadID) {
    int x = id.x, y = id.y;
    if (x <= 0 || y <= 0 || x >= _Width-1 || y >= _Height-1) return;
    float lap = 0;
    // 상하좌우 4개는 +1, 중심은 -4 (회색조 = RGB 평균)
    [unroll] for (int k = 0; k < 5; k++) {
        int2 o = int2(k==1?-1:k==2?1:0, k==3?-1:k==4?1:0);
        float w = (k==0) ? -4 : 1;
        float3 c = _InputTex.SampleLevel(samplerPointClamp, (float2(x,y)+o+0.5)/float2(_Width,_Height), 0).rgb;
        lap += w * (c.r + c.g + c.b) / 3.0;
    }
    _Lap[y * _Width + x] = lap;
}
```

- 픽셀마다 독립인 계산이라 GPU에 잘 맞습니다
- 영역별 평균·분산 집계는 결과 버퍼를 받아 CPU에서 했고, 전체 **20ms 남짓**으로 줄었습니다. 집계까지 GPU 리덕션으로 옮기면 더 줄일 수 있습니다
- 결과를 CPU로 가져오는 것 자체가 비용이므로, 이 검사는 매 프레임이 아니라 **필요한 시점(시작 전, 주기적)**에만 돌립니다

## 5. 한계

- 원래 디테일이 적은 장면(흰 벽 등)은 렌즈가 깨끗해도 점수가 낮습니다. 얼굴이 화면에 있을 때만 판단하거나, 얼굴 주변 영역을 쓰는 편이 안정적입니다
- 역광·노출 문제는 분산보다 밝기 히스토그램 지표가 맞습니다

## 정리

- "비정상"의 범위를 기존 기능과 겹치지 않게 먼저 좁힌다
- 흐림은 학습 모델 없이 영역별 라플라시안 분산으로 충분했다
- 픽셀 독립 연산은 Compute Shader로 — CPU 200ms+ → GPU 20ms대
