얼굴 기반 실시간 파이프라인은 보통 모델 여러 개로 이루어집니다. 얼굴 검출 → 랜드마크(얼굴 메시·홍채) → 머리 자세 → 안경 착용 같은 속성 판별. 처음에는 단순하게 매 틱(예: 100ms마다) 전부 돌리거나, 필요해 보이는 것을 매 틱에 하나씩 추가하게 됩니다. 저사양 기기에서 특정 모드만 틱이 목표 주기를 크게 넘는 문제를 추적하면서 정리한 방법입니다.

## 1. 어디서 늦어지는지부터 — 구간 계측

틱 하나를 모델별 구간으로 나눠 진단 로그에 남기도록 했습니다. 그러자 원인이 바로 보였습니다.

- 느린 모드에서만 **머리 자세를 매 틱** 추론하고 있었고
- 그 블록에 나중에 추가된 **속성 판별 모델이 같이 붙어** 매 틱 돌고 있었습니다
- 랜드마크 모델 자체의 시간은 예전과 같았습니다. 모델이 느려진 게 아니라 **매 틱 하는 일이 늘어난 것**이었습니다

또 하나: 틱 시작 조건을 렌더 프레임마다 한 번만 확인하면, 조건이 충족된 직후에도 다음 프레임까지 기다리는 대기가 생깁니다. 한 프레임 안에서 여러 지점(업데이트 직후, 늦은 업데이트, 프레임 끝)에서 확인하도록 바꿔 평균 대기를 줄였습니다.

## 2. 주기를 정하는 기준 — 유지 오차 vs 모델 자체 오차

"자세를 1초마다만 추론해도 되는가?"를 감으로 정하지 않고 숫자로 비교했습니다.

- 매 틱 자세를 기록한 과거 데이터에서, 자세 값을 1초 동안 유지했을 때 생기는 오차를 계산했습니다(참값은 매 틱 값을 짧게 평활한 추세로 근사)
- 그 오차를 **머리 자세 모델 계열의 공개 벤치마크 정확도**(예: 6DRepNet의 MAE 3~4°)와 비교했습니다
- 1초 유지 오차는 중앙값 0.5° 안팎, 상위 10%에서 2.5° 안팎으로, **모델 자체가 원래 갖는 오차보다 작았습니다**

모델 오차보다 작은 오차를 줄이려고 매 틱 비용을 내는 것은 비효율이라는 판단으로 1초 주기를 채택했습니다. 대신 판정에 쓰는 지표의 하위 꼬리가 조금 넓어지는 대가를 숫자로 적어 두고, 그 맞바꿈은 담당자가 결정하도록 했습니다.

## 3. 같은 틱에 겹치지 않게 배치

주기를 나눠도 무거운 모델 두세 개가 같은 틱에 몰리면 그 틱만 튑니다. 시작 시각을 엇갈리게 배치했습니다.

| 추론 | 주기 | 도는 시각 |
|---|---|---|
| 랜드마크 | 매 틱 | – |
| 얼굴 검출 | 2초 | 0, 2, 4초… |
| 머리 자세 | 1초 | 0.5, 1.5, 2.5초… |
| 속성 판별 | 6초 | 1, 7, 13초… |

처음엔 속성 판별을 5초로 했다가 10초마다 검출과 겹쳐 6초로 바꿨습니다. 단, 추적 시작·재개 첫 틱이나 얼굴이 크게 움직여 강제 재검출이 필요할 때는 예외로 둡니다.

결과적으로 느린 기기에서 문제 모드의 틱 중앙값이 목표 주기(100ms)에 닿아 다른 모드와 같아졌습니다.

## 4. 시도했지만 버린 것

| 시도 | 결과 |
|---|---|
| 자세·랜드마크를 동시에(병렬) 실행 | 틱은 줄었지만 화면 fps가 떨어짐 — 렌더링과 CPU를 다툼 |
| 자세 모델만 GPU로 | 저사양 GPU에서 메모리 부족으로 연산이 실행되지 않음 |
| 작업 스레드 수 늘리기 | 데스크톱에선 빨라졌지만 기기에선 차이 없음 |
| 그래프 노드 정리(상수 접기) | 런타임이 로드 시 이미 접고 있어 실행 레이어 수가 같음 |
| 가중치 양자화(FP16·UINT8) | 파일만 작아지고 **계산은 FP32라 오히려 느려짐**, UINT8은 출력도 크게 바뀜 |

마지막 항목은 자주 오해되는 부분입니다. 가중치만 압축해 저장하는 양자화는 로드할 때 다시 FP32로 풀어 계산합니다. 정수 연산으로 빨라지려면 **정수 커널을 가진 런타임**(TFLite, ONNX Runtime의 INT8 경로 등)을 써야 하고, 그때도 출력 변화를 따로 검증해야 합니다([ONNX Runtime 양자화 실험](/blog/onnx-runtime-quantization-agreement/)).

## 정리

- 틱을 모델별 구간으로 계측하면 "모델이 느려졌다"와 "할 일이 늘었다"가 구분된다
- 주기는 "유지로 생기는 오차"를 "모델 자체 오차"와 비교해 정한다
- 무거운 추론은 시각을 엇갈려 같은 틱에 몰리지 않게 한다
- 가중치만 압축하는 양자화는 속도를 올려 주지 않는다
